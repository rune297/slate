# Slate

> 一块贴着屏幕顶边的石板。不占桌面、不抢焦点，需要时从顶部拉下来，用完随手丢掉。

Slate 是一个 Windows 优先的本地桌面工作台：待办、速记、链接、录音、常用软件启动，全部收在一块从屏幕顶部下拉唤出的面板里。所有数据只存在本机。

---

## 它解决什么问题

桌面效率工具普遍卡在一个矛盾上：**常驻会碍事，不常驻就想不起来用。**

- 常驻侧边栏 / 悬浮球：占掉一块屏幕，为了"随时能用"付出永久的空间代价
- 快捷键唤出：效率最高，但**可发现性为零**——你得先记住它存在
- 需要打开主窗口的：光是"打开"这个动作，就足以劝退一次一闪而过的念头

Slate 的答案是：**平时完全不存在，唤出方式符合直觉且不需要记忆，收起后不留下任何痕迹。**

---

## 核心交互：为什么是「下拉手势」而不是「鼠标移上去就显示」

这是本项目最关键的一次设计决策。备选方案有两个，判定标准是三条：**唤出成本、误触率、可发现性**。

决定胜负的是第二条——误触率。

| | Hover 即显示 | 下拉手势 |
|---|---|---|
| 唤出成本 | 最低（移到顶部即可） | 稍高（移到顶部 + 向下推 40px，约 300ms） |
| 误触率 | **高** | 极低 |
| 可发现性 | 高 | 高 |

**hover 只在一种前提下成立：那条边缘是系统独占区。** macOS 菜单栏、自动隐藏的任务栏都符合——下面没有别的 UI 跟它抢，鼠标经过就是冲着它来的。

Windows 的屏幕顶部恰恰是全桌面竞争最激烈的地带：最大化窗口的标题栏、浏览器标签栏、最小化/关闭按钮。用户工作时鼠标几分钟就要上顶一次，**每一次都是误触候选**。用 0 学习成本换来的，是每天几十次"我没想打开它"。

下拉手势多付出的约 300ms，换来的是**触发需要一个完整的意图序列**——单次经过不会命中。这笔交易划算。

### 一个必须解决的坑：拖窗口和下拉手势，鼠标轨迹几乎一样

把窗口从最大化状态往下拉还原，轨迹和"下拉手势"在坐标层面无法区分。唯一可靠的区分信号是**按键状态**：拖窗口按住左键，手势是空手移动。

而 Electron 主进程的 `getCursorScreenPoint()` 只有坐标，没有按键。所以 Slate 额外铺了一层**穿透感应层**（`hotzone.html`）：一个完全透明、`setIgnoreMouseEvents(true, { forward: true })` 的窗口——点击直接穿透到下层应用，不影响用户点标签页或关闭按钮，但仍然接收鼠标移动消息，从而能读到 `e.buttons`。**按住任意键一律判定为"在拖东西"，放弃本次手势。**

## 另一个坑：点面板外面关不掉

这个 bug 的表象是"唤出后想放弃，点外部没反应，面板一直杵着"。根因不在状态机，在 Windows 的焦点规则：

1. Windows 只有**前台进程**或**刚收到输入事件的进程**才能抢走焦点
2. 原设计用空格键唤出时，进程收到键盘输入 → 抢焦点成功 → 一切正常
3. 改成鼠标手势后，整个唤出过程**没有任何输入事件进到这个进程** → `SetForegroundWindow` 被系统拒绝 → 面板始终无焦点
4. 收起的唯一入口是窗口失焦（`blur`）——它本来就没有焦点可失，`blur` 永远不会触发

这也解释了那个反直觉的现象：**点过面板内部之后再点外部，往往就能关掉**——那一次真实点击才把焦点给了它。

**修法：新增一条完全不看焦点的判定**（90ms 轮询，仅在展开时运行）：

- 光标离开面板范围（含 16px 容差）并停留 300ms → 收起，且这一下点击照常落到下层应用，不被吞掉
- 真拿到过焦点又丢失 → 立即收起（补 `blur` 漏发）
- 三道防误判：展开后 600ms 内不判定（等动画）、唤出瞬间光标若不在面板内则延后 2.5s 再判定、系统授权弹窗期间不收起

### 顺带：为什么收起是"移出屏幕"而不是 `hide()`

窗口一隐藏，Chromium 会把页面定时器降频到每分钟一次——待办到期提醒会走不准。所以收起时是把窗口 `setBounds` 到屏幕上方之外，保持"可见"状态，同时开启 `backgroundThrottling: false` 双保险。

## 功能

- **待办（视角化）**：今天 / 已排期 / 收件箱 / 已完成四个时间视角，过期自动并入「今天」；分类可自定义增删改名，条目可一键「加入今天」、点分类徽标循环换类；快速添加支持自然语言日期（「明天 14:30 交稿」「周五 20:00」自动解析）；保留日历选择器、剩余时间徽标、到期前 1 小时提醒、批量删除
- **主题**：暖白纸感（默认）/ 深灰，设置中切换或跟随系统，防闪启动
- **速记**：随手记录，支持搜索与归档
- **链接**：粘贴网址自动抓取标题并分组
- **录音**：本地录音 + 转写（需配置 API Key，用系统安全存储加密）
- **快速启动**：自定义常用软件，点一下直接打开；已在运行的实例会被带回前台
- **剪贴板历史**（默认关闭，设置中开启）
- **Codex / Claude 任务完成提醒**：本地 WebSocket 通知服务

## 技术栈

- Electron 44 + 原生 JavaScript（无前端框架，无构建步骤）
- `electron-builder` 打包（Windows NSIS / macOS DMG）

### 本地运行

```bash
# 需要 Node 22.12+
npm install
npm start          # 启动应用
npm test           # 运行测试（107 个单元用例 + 3 个 Electron 端到端脚本，e2e 需真机桌面）
npm run build:win  # 打出 Windows 安装包
```

### 项目结构

```
main.js            主进程：窗口管理、唤出手势、收起判定、任务通知
main-services.js   数据持久化、录音转写、链接抓取等业务服务
platform.js        平台差异：窗口尺寸与位置策略
preload.js         渲染层 IPC 桥接
hotzone.html       穿透感应层（读取按键状态以区分拖窗口与手势）
dismiss.html       全屏穿透层（面板展开时检测外部点击）
renderer/          面板 UI 与业务逻辑
tests/             单元测试与 Electron 启动冒烟测试
```

关键可调参数集中在 `main.js` 顶部常量区：`TOP_REVEAL_MODE`（`gesture` / `hover` / `off`）、`TOP_REVEAL_PUSH_PX`（手势幅度）、`TOP_REVEAL_DWELL_MS`（悬停唤出停留时长，默认 500ms）、`DISMISS_ON_LEAVE`（有焦点时是否「移开即收」，默认关——收起以「点击面板外」为准，无焦点场景自动退回移开即收）、`WIN_PANEL_LIMITS`（面板尺寸）。收起判定的完整规则见 `tickDismissPolling` 与 `blur` 处理器：有焦点 = 失焦即收（光标在面板内则豁免）；无焦点 = 移出面板 300ms 即收。

## 已知限制与遗留问题

- **默认唤出快捷键是 Space，实际注册不可用**：建议安装后在 设置 → 唤出快捷键 改为 `Control+Alt+S` 之类的组合；顶栏悬停 + Space 仅在光标停留于顶部条时生效
- **端到端测试需真机桌面**：`tests/*.electron.js` 依赖 GPU 合成，在无头/锁定屏幕/受限会话下会报 `GPU process exited` 与 `ERR_FAILED`（单元测试 107 个不受影响）；近期待办重设计后 e2e 用例已同步改写但未在真机重跑
- **浅色主题视觉细节未逐项校对**：阴影浓度、收起态 38px 细条在浅色壁纸上的可见性，需实机确认
- **深色/浅色原生 select 弹出层**依赖 `--select-popup-bg` 实底令牌，改主题时勿删
- 无云同步、无自动更新，升级需手动下载安装包覆盖安装（卸载会保留数据）
